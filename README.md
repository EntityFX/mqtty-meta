# Измерение MQTT-брокеров и проверка их моделей в MqttY

Проект связывает настоящий эксперимент и моделирование. MqttBenchmark измеряет брокер сообщений; MqttY строит по этим данным его двойник. Затем двойник сравнивается с новыми измерениями, которые не использовались для настройки.

Цель — получить **повторяемую модель с известной точностью и границами применимости**. Полностью выполненный прогон ещё не означает, что модель точна.

## Структура

| Каталог | Содержание |
| --- | --- |
| `MqttBenchmark/` | Git-подмодуль: настоящая MQTT-нагрузка, управление стендом, измерения и агрегация |
| `mqtty/` | Git-подмодуль: симулятор MqttY, калибровка двойников, эксперименты и графический редактор |
| `diss/` | Git-подмодуль: исследовательские тексты и средства сборки публикации |
| `tools/campaign/` | Общие сценарии подготовки и выполнения серий, продолжения и подготовки отчётов |
| `docs/` | Руководства, архитектура, метрики и описания четырёх брокеров |
| `reports/` | Опубликованные результаты и история проверок |

Подмодули получают вместе с корневым репозиторием:

```bash
git clone --recurse-submodules https://github.com/EntityFX/mqtty-meta.git
cd mqtty-meta
```

Для уже существующей копии без подмодулей: `git submodule update --init --recursive`. Версии исходников фиксируются до начала опыта. Автоматический запуск новой серии описан в [руководстве](docs/full-campaign-runbook.md); он рассчитан на Linux с systemd и cgroup v2. Программы измерения и научных симуляций используют .NET 6, отдельный графический редактор — .NET 8.

Полная программа содержит **1512 основных запусков**, сокращённая — **756**. Для каждого брокера выполняются измерения для настройки, построение профиля, проверка модели на исходных данных, новые измерения, независимый контроль и модель сети Relay. Точность проверяется по прежним критериям; полное покрытие и успешное завершение процессов сами по себе её не доказывают.

Объём исходников по каждому модулю, метод подсчёта и назначение классов приведены в [архитектуре](docs/architecture.md). Пересчитать таблицу: `python tools/code-inventory.py` (Python 3.11+ и Git).

В `reports` находятся опубликованные отчёты, графики, таблицы и снимки результатов **на дату, указанную в документе**. Это не текущий статус стенда. В `reports/history` сохранены отчёты о прежних проверках и исправлениях.

Подробные журналы сообщений и архивы натурных опытов хранятся на диске результатов. Их пути и контрольные суммы перечислены в приложениях к отчётам. Одна копия репозитория не заменяет исходные архивы.
