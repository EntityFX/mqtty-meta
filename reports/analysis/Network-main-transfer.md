## Почему служба в failed

При получении данных `MainPID=0`, `Result=exit-code`, `ExecMainStatus=1`, `ActiveState=failed`. Сохранённый `progress.json` указывает `budgetExhausted`, причина `executionBudgetExhausted`. Журнал показывает первоначальную остановку и прежнее продолжение с отдельным ресурсным решением; в этом переносе служба не возобновлялась.

В реестре **109 попыток для 108 разных ключей**, включая три неудачные попытки:

| Ключ | Причина | Состояние после всех сохранённых попыток |
| --- | --- | --- |
| `matrix.line.relay.q2.r5000.w10.s43` | `RuntimeError: jobRssLimit`, код −9 | Есть последующая успешная попытка того же ключа; исходный отказ сохранён |
| `matrix.ring.federation.q2.r5000.w10.s43` | `RuntimeError: executionBudgetExhausted`, код −9 | Нерешённый отказ |
| `matrix.ring.federation.q2.r5000.w10.s44` | `RuntimeError: executionBudgetExhausted`, код −9 | Нерешённый отказ |

Три failed-попытки не означают три отсутствующие точки: одна точка восстановлена ранее. Сохранённое состояние содержит 16 предупреждений, их научный смысл требует разбора исходных событий.

## Следующий шаг без Linux

Выполнить чтение первичных событий 106 доступных результатов существующим проверяющим кодом, затем строить сравнение по фактически полным группам. Показать предупреждения, недоставку и применимость задержек; пропуски не заполнять короткой серией. Отдельно оформить решение о недостающих 56 точках и шести повторах: старый исчерпанный срок не сбрасывать и всю матрицу с нуля не начинать.
