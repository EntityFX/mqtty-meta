# Окончательный профиль статьи 1: проверка через Linux Web

Подтверждён путь **API → очередь Web → отдельный процесс → результаты** для сохранённого профиля новой серии. Это техническая приёмка оболочки; основная натурная серия 40/40 не повторялась и не менялась. [Программа проверки](../../docs/plans/MqttY.Web.final-profile-check.md) оформлена до запуска.

## Развёртывание

После перезагрузки Web не работал, диск hd250 не был подключён. Данные опытов обнаружены после подключения. Прежний Web-релиз относился к commit b7537bd; для актуального формата опубликован отдельный релиз неизменённого mqtty commit **4c658536586f88a89cd3ff5ab0915903640cf3c9**. Исходники модели не дорабатывались. Прошли три существующих теста одиночной проверки, включая отклонение изменённого профиля в адаптере.

Проверены SHA 63 файлов опубликованного payload. Старый релиз и конфигурация службы сохранены. Перед запуском порт был свободен, живого Web-процесса не было; в истории 60 завершённых и три отменённых задания, незавершённых нет. Служба запущена с прежними ограничениями: один worker, 2 ГиБ, CPU 150%, loopback 5088. Frozen runtime основной серии не заменялся.

По итоговому снимку: служба active/running, PID host **3780**, приложения **3783**, `/healthz` отвечает ok, выполняемых и ожидающих заданий 0. Состояние относится к моменту этой проверки и не является постоянным мониторингом. [Развёртывание](../audits/web/article1-final-profile-v1/deployment.json), [последний снимок](../audits/web/article1-final-profile-v1/transfer.json).

## Проверка профилей и исполнения

В рабочий каталог Web скопированы побайтно четыре окончательных профиля, затем через API созданы отдельные пресеты «Статья 1 — …, итоговый профиль». Существующие пресеты по умолчанию не менялись. Это подготовка входов файловым копированием, а не проверка браузерной загрузки JSON.

Для Aedes, Mosquitto, ActiveMQ и EMQX API подтвердил точный режим 16 байт / QoS 1 / 16 отправителей. Все четыре запроса с отсутствующей точкой 1 отправитель отклонены с HTTP 400. SHA снимков соответствуют оригиналам; соседние режимы не подставлялись.

Исполнен один короткий Aedes: seed 42, прогрев 0,01 с, подача 0,1 с и наблюдение ещё 0,1 с, tick 10 мкс. Имя задания — Final profile API check Aedes; ID `da613d0b932d42739fb62e8b1fa5e52e`. Aedes выбран первым по порядку, не по точности результата. Весь блок исполнения и прямого сравнения занял около 6,12 с.

Web сообщил **21 014 тиков и 64 966 шагов**. Фактическая подача — от 0,01014 до 0,11014 модельной секунды; конец наблюдения — 0,21014. Две отдельные реализации пересчёта заново соединили ID, исходы и доставки, подтвердили показатели, гистограммы и непрерывность подключения подписчика. Прогревочные события исключены из измеряемой группы.

Побайтно совпали шесть файлов: summary, гистограмма публикационных задержек, журналы публикаций, доставок и подписок, границы фаз. Отдельно совпали научные поля counters: brokers, receivers, receiverScope. Все даты и служебные manifests не объявляются одинаковыми. Входы четырёх профилей и 54 файлов сохранённого runtime основной серии проверены повторно.

Перенесены и проверены SHA **37 файлов**, 2 231 924 байта до сжатия. Полные события и бинарные файлы остаются вне Git; [квитанция](../audits/web/article1-final-profile-v1/verification.json), [побайтовое сравнение](../audits/web/article1-final-profile-v1/comparisons.json), [профили и запросы](../audits/web/article1-final-profile-v1/profiles.json).

## Границы и оставшаяся работа

Этот опыт подтверждает конкретный API-путь нового профиля. Полный браузерный сценарий, удобство редактора и серийная работа с тысячами заданий здесь заново не проверялись. Новый независимый натурный эталон к сравнению Web не привязан: интерфейс получает reference из калибровочного профиля. Зелёные критерии такого сравнения не являются независимой проверкой точности по новому контролю.

Основные 40 запусков статьи 1 по-прежнему выполнены отдельным Probe. Короткая проверка Web не добавляется к их выборке. Её задача — показать сохранение вычисления при смене оболочки запуска. На другом оборудовании истинность профиля настоящего брокера этим опытом не проверяется.

Первая попытка нового локального проверяющего скрипта повторно использовала уже исчерпанные итераторы событий для второго пересчёта. Причина подтверждена отдельным чтением тех же журналов; события материализованы перед передачей двум независимым алгоритмам. Исходные журналы и критерии не менялись, обе реализации после этого дали одинаковые значения.

Следующая техническая задача — подключить сохранённый независимый натурный контроль с его SHA и явно показать его отличие от калибровочного reference; затем выполнить браузерную приёмку этого пути. Основной текст диссертации остаётся за автором.
