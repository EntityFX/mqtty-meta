Результат: [рабочий словарь](../../../../docs/dissertation/metrics-contract.md). Это документальная сверка существующих определений, не новая программа опытов и не акт авторского согласования шага 05.

## Что проверено и где проходит граница

Прочитаны актуальные исходники MqttBenchmark и MqttY, `docs/mqtt-benchmark/metrics.md`, прежний `docs/overview/measurement-contract.md`, принятые пакеты `article-1-matched-main-final-v1` и `network-main-final-v1`, а также новый Web `NativeControlCohort/NativeControlReference`. Исходные git blobs исторических реализаций сопоставлены с blobs текущего HEAD. Контрольные суммы файлов, просмотренных для выводов, находятся в [sources.csv](sources.csv); версии и сравнение выбранных исторических исходников — в [frozen-sources.csv](frozen-sources.csv).

На момент сверки HEAD мета-репозитория — `471f7c60b9cb1ce0c7e55dddd704a6365a2820ae`, MqttBenchmark — `ab513df3d2b65462abcfba8084f066ae4b1bd0a1`, MqttY — `f5c0a4715b555c4348d2a2843177251f62c640ff`. Квитанция фиксирует именно эти входы. Текущие исходники не объявляются кодом, исполнявшим всю историю кампаний.

Для статьи 1 основание — `article-1-main-execution-v1/admission.json` и `runtime-manifest.json`: Benchmark `ab513df3d2b65462abcfba8084f066ae4b1bd0a1`, MqttY `4c658536586f88a89cd3ff5ab0915903640cf3c9`, source Probe `43eef6b`. Сохранённая приёмка сообщает 40 комплектов raw и 1680 сравнений полей. Настоящая сверка не является повторным пересчётом этих raw.

Для основной сети основание — `network-main-final-v1/source-metadata/execution-manifest.json`: `runtimeSourceCommit=12601f534f9da3673057b072f8bd6a0c67fd8aed`. Отдельные `sourceRevisions` содержат мета-исполнитель `8882aada0eb677f101d03fac9387cf32224affad` и его MqttY checkout `3327b118fb4d6683fe8e8f30a074175b2479c29b`: это разные роли, их нельзя подставлять вместо runtimeSourceCommit. Полная приёмка находится в `acceptance.json` (162 точки, 6 повторов), а старое `mainCampaignComplete=false` внутри `raw-recount/verification.json` не редактировалось. Полные raw остаются во внешних архивах; в этой работе они не распаковывались и заново не проверялись.

`frozen-sources.csv` сравнивает сохранённые git blobs исторического commit с git blobs зафиксированного текущего HEAD. SHA рабочего файла приводится отдельно в `sources.csv`; равенство git blobs не требует совпадения кодировок окончания строк рабочей копии. Проверяются выбранные классы учёта и исполнения, а не весь runtime или двоичная сборка. SHA подтверждает точность привязки, а смысл проверен чтением методов.

## Расхождения, которые нельзя сглаживать

| Предмет | Актуальные/исторические поля | Как отражено в словаре |
| --- | --- | --- |
| Попытка API и брокерный допуск | Натурный `attempt` и сетевой `apiAttempts` находятся перед API; брокерные `attempted/admitted` — другой уровень | A относится к названному журналу; offered/scheduled и admitted отделены |
| Pending | Benchmark Snapshot требует все исходы; статья 1 и Web сохраняют pending; общий брокерный остаток не сопоставлен по ID | Баланс `A=C+F+P` только для одной когорты; P не переименован в failure |
| Окно C/T | Benchmark `completedRps` использует actualMeasurementSeconds; статья 1 `completedCohortPerSubmissionSecond` и Web rps используют фиксированную подачу с исходами до h; сеть sourceCompletedRps — исходные модельные завершения с drain / measurement | Раздельные подписи; дополнительно `completedRpsInWindow` только до e |
| Успешный ID против всех попыток | `deliveryLossRate=1−completedIdsDelivered/completedPublishes`; EST-доставка — `uniqueDeliveries/attemptedPublishes` | `Dс/C` и `D_id/A` не взаимозаменяемы |
| Несколько receivers | Основная сеть `E=apiAttempts×receivers`, `D_pair=uniqueDeliveries`; не `completed×receivers` | Отдельные `L_pairs`, fullyDeliveredPublications и пример |
| Прежний Relay | expected/delivered — внутренний fanout; receivers — события после reset, с возможными поздними warmup-получениями | Не считается новым сквозным ID-учётом |
| Goodput | В сети D_pair/T; у Benchmark отдельного поля goodput нет | Предлагаемое название всегда с объектом счёта; новых полей реализации не приписано |
| Пустой знаменатель | Benchmark и общий Relay пишут 0; когортный пересчёт/Web пишут null; сеть loss при E=0 — null | Сохраняется машинное соглашение и отдельно «не оценивается» |
| p99 | Публикационный p99 и p99 первого получения — разные выборки/концы интервала | QoS 0 ACK-p99 неприменим; receiver-p99 QoS 0 применим; среднее p99 не pooled p99 |
| Прогрев/drain | Старые натурные журналы без точной общей границы; статья 1 с sharedMonotonic и фиксированным горизонтом; новая сеть warmupDrain до reset | Новые фазы не приписаны старой кампании |
| Дубликаты | Benchmark — по ID включая неожиданные; статья 1 — только выбранная когорта/горизонт; сеть — по паре; suppressedDuplicates — фильтр импорта | Разные области счёта перечислены явно |
| Topic+payload и транзит | forwardTopicPayloadBytes по логическим попыткам; физические counters звезды — measurement+drain после warmupDrain | Входящие и исходящие bytes не суммируются как уникальные данные; весь Ethernet-трафик не заявлен |
| CPU/RSS | Capture, внутренние интервалы нагрузки и ресурсы процесса симулятора имеют разные окна/объекты | Для EST оставлены натурные внутренние интервалы; модель CPU/RSS брокера не заявлена |
| EST/EST* | Четыре веса 1/4 для QoS 1/2; три веса 1/3 для QoS 0 | Сохранены прежние правила; нет новой EST для основной сети/Web |
| Web без контроля/с контролем | TwinValidationAdapter без NativeControlReference — сравнение с калибровочным профилем; с пакетом — отдельный натурный контроль после freeze | Не объявляется слепой независимостью разработки; импорт не пересчитывает первичные натурные журналы |
| Web и история | Новый код импортирует metadata, вызывает тот же runner и сохраняет результат; принятые серии выполнялись отдельными приложениями | Установленному Linux Web не приписано исполнение основных 40/40 или 162+6 |
