# Потоковое сохранение результатов федерации

В отдельной рабочей версии MqttY устранены два дополнительных выделения памяти пропорционально размеру файла: создание полной JSON-строки перед записью и чтение полного файла для SHA-256. Замороженный Linux runtime и обе неуспешные попытки не изменены.

## Основание

Сетевой pilot `pilot.star.federation.q0.r5000.w10.s42` завершился кодом −6 и сообщением `Out of memory.`. После summary и publications отсутствуют transmissions, receipts и seals. Это подтверждает нехватку памяти и незавершённость экспорта. Порядок записи указывает на сериализацию transmissions как вероятный участок отказа; точная неудачная аллокация без stack/dump не установлена. Подробные доказательства сохранены в соседнем аудите `network-pilot-tail-failure-v1`.

Исправление устраняет подтверждённую лишнюю буферизацию, но пока не доказывает успешное прохождение исходного большого pilot. Второй отказ, timeout модельного drain для QoS 1, этим исправлением не устраняется.

## Что изменено

- `FederationResultWriter.Json` сериализует непосредственно в файловый поток временного файла. Настройки JSON, порядок данных, кодировка UTF-8 и переименование после успешного закрытия файла сохранены. При исключении незавершённая запись не заменяет прежний целевой файл.
- Вычисление SHA-256 читает файловый поток через `SHA256.ComputeHash`, совместимый с .NET 6. Для хэширования больше не создаётся массив размером с журнал.
- Алгоритмы MQTT, очередь, нагрузка, profile lookup, seed, критерии и scientific summary не менялись. Полный ledger и массивы snapshots по-прежнему находятся в памяти: общего ограничения памяти всей симуляции это изменение не устанавливает.

## Проверка

Три теста проверяют байты относительно прежнего `JsonSerializer.Serialize`, включая записи публикаций, пересылок, бинарный payload, словарь гистограммы, enum, null и русский текст; сохранение целевого файла при ошибке; расход управляемых выделений при большом экспорте и потоковом SHA. Отдельно выполнены **141/141** регрессионных тестов федерации, балансировщика, MqttRelay и профилей.

В искусственном тесте JSON размером **10 275 003 байта** потребовал менее **100 КБ управляемых выделений** при записи. SHA файла **8 МиБ** потребовал менее **9 КБ**. Точные значения находятся в TRX и машинном receipt. Это измерение `GC.GetAllocatedBytesForCurrentThread` на фиксированном тесте после прогрева, **не RSS процесса**, не пиковая память реального pilot и не коэффициент ускорения.

Подтверждения: `federation-regression.trx`, `verification.json`. Команда проверки из корня метарепозитория:

```powershell
dotnet test mqtty/src/EntityFX.MqttSimulator/EntityFX.Tests.Integration/EntityFX.Tests.Integration.csproj -c Release --filter "FullyQualifiedName~Federation|FullyQualifiedName~LoadBalancing|FullyQualifiedName~MqttRelay|FullyQualifiedName~BrokerProfile"
```

## Следующий проверяемый шаг

Перед новым Linux-опытом зафиксировать отдельный source/runtime snapshot и неизменённый конфиг, измерить память процесса и службы. Сравнить сохранённые научные данные с доступной частичной попыткой, а полный результат проверить по всем журналам. Старую попытку оставить failed. Новый runtime не подменяет замороженный и не получает автоматически допуск к основной матрице. Для QoS 1 отдельно диагностировать очереди и pending на границе drain; увеличение времени ожидания не считать исправлением протокола.
