# Два разных отказа сетевых pilots

Подтверждены **27 проверенных успешных pilots, два технических отказа и одна незапущенная точка**. Основная матрица не допущена. Замороженные входы, runtime и исходные попытки не изменялись; повторные симуляции не запускались.

## Что проверено

Независимо от сохранённого `progress.json` повторно выполнен исходный замороженный `verify_output` для всех 27 успешных попыток. Проверены seals, raw-публикации и доставки, гистограммы, соответствие конфигураций, GraphML, SHA научных файлов и равенство summary с receipt. Проверка заняла 35,6 секунды, расхождений нет. Это проверка сохранённых данных, а не повторная симуляция: побайтная воспроизводимость всей матрицы пока не проверена.

## Отказ QoS 0: памяти не хватило при сохранении результата

Точка `pilot.star.federation.q0.r5000.w10.s42`, попытка 1. Единственная строка журнала дочернего процесса — `Out of memory.`; код возврата −6 соответствует аварийному завершению SIGABRT. Это **не сообщение Stack overflow**. Отдельная очередь остатка остановилась с кодом контроллера 1, последняя QoS 2 точка не запускалась.

Summary, run-config и publications успели сохраниться. `transmissions.json`, `delivery-receipts.json`, manifest, гистограммы, топология и seals отсутствуют. Само слово completed в незавершённом наборе файлов **не делает опыт успешным и верифицированным**. Значения этой строки приводятся только для диагностики; они не включаются в научное сравнение успешных опытов.

Исходный `FederationResultWriter.Write` сохраняет summary, затем publications, затем transmissions. Его метод `Json` сначала строит целую JSON-строку через `JsonSerializer.Serialize`, затем передаёт её `File.WriteAllText`. Поэтому граница сохранившихся файлов указывает на этап подготовки экспорта transmissions. Для 450 тысяч межброкерных пересылок, локальных доставок и исходных публикаций здесь существует крупная дополнительная буферизация. Перед экспортом также создаются массивы snapshot и forwards.

**Подтверждено:** сообщение runtime о нехватке памяти и незавершённый экспорт. **Сильный кандидат:** большой временный JSON-буфер при экспорте transmissions. Точная неудачная аллокация не записана: managed stack/dump отсутствует. Нельзя объявлять её доказанной только по порядку файлов.

**Не подтверждено:** убийство процесса ядром Linux из-за cgroup OOM. В журнале службы нет `oom-kill`; запрос kernel journal не вернул записей. Cgroup после завершения удалена, её `memory.events` недоступен; отсутствие записей не доказывает отсутствие событий. Пик RSS, измеряемый с интервалом, не устанавливает мгновенный расход памяти. Не следует устранять проблему простым увеличением лимита и объявлять это исправлением модели.

Минимальная доработка: писать JSON потоком в временный файл, сохраняя прежние настройки сериализации и атомарное переименование. Тесты должны сравнить старые и новые байты на репрезентативных данных, независимо проверить JSON и SHA, а также измерить расход памяти на большом искусственном журнале. Это отдельный runtime: исходную frozen-серию им не подменять. При дальнейшем росте данных следующая мера — потоковый ledger; она шире минимального исправления и требует отдельной проверки порядка записей.

## Отказ QoS 1: исчерпан модельный drain

Точка `pilot.star.federation.q1.r5000.w10.s42`, попытка 1, осталась прежней: CLI 2, `System.TimeoutException: drain timed out; partial evidence retained.`. Пять модельных секунд drain исчерпаны; 50 000 исходных завершений и 58 581 полученная пара из 200 000. Счётчик отказов очередей федераторов 255 912. Это другой отказ, он не объясняется автоматически ошибкой экспорта QoS 0.

По сохранённым данным нельзя отделить долгий хвост очередей от зависшего pending QoS. Нужны отдельные счётчики состояния на границе drain и минимальные тесты отказа сетевой отправки. Увеличивать drain или менять runtime внутри замороженной серии нельзя. p99 только полученных сообщений не характеризует задержку неполученных пар. Полный разбор этой попытки сохранён в прежнем `network-pilot-failure-v1/Diagnosis.md`.

## Допуск и следующие действия

1. Оставить обе попытки failed; не переименовывать незавершённый экспорт в успешное измерение.
2. Исправить подтверждённую лишнюю буферизацию JSON на отдельной версии, проверить байты и память тестами. Исходный Linux runtime сохраняется.
3. Добавить отдельную диагностику очередей и pending QoS для timeout, затем установить причину. Исправление writer не доказывает устранение drain timeout.
4. Оформить новую версию диагностической программы и входы для затронутых точек. Для полного научного сравнения принять явное решение о сопоставимости версий; не смешивать runtime как одну неизменную серию.
5. Последняя точка `pilot.star.federation.q2.r5000.w10.s42` пока не запускалась. 30/30 завершённого пилотного покрытия нет.
6. Замороженный runner требует технически проверенных всех pilots, `results-pilot.json` и связанного по SHA решения. Сейчас `results-pilot.json` отсутствует; оснований для запуска основной матрицы 162 + 6 нет.
