# Проверка MqttY.Web на Linux

Служба `mqtty-web.service` запущена на `127.0.0.1:5088`. Проверены отдельные процессы всех трёх существующих научных движков через HTTP. Мониторинг сохраняет PID, RSS, HTTP-состояние и объём данных на hd250. Исходный релиз сохранён отдельно; замороженные кампании не менялись.

После проверки обновлены только четыре файла интерфейса из коммита `3327b118fb4d6683fe8e8f30a074175b2479c29b`: высота топологии и перемещение узлов мышью. SHA-256 всех DLL совпали с предыдущим проверенным релизом, а четырёх ресурсов по HTTP — с новой сборкой. Служба обновлена после подтверждения отсутствия выполняющихся и ожидающих заданий. Текущий PID монитора `88937`, Web `88940`, ответ `/healthz` — 200. Новый релиз `e29d860594f09e68f12026a3efc82629b01b546f5541e52761fe3d97fca2b2b9`; предыдущий сохранён. Подробности — `ui-update-receipt.json`.

Все девять заданий завершились; 141 файл проверен по SHA-256, HTTP summaries совпали с запечатанными файлами. Дочерние PID наблюдались во время работы, а не были выведены из названия задания. Это проверка работоспособности развёртывания, не доказательство точности моделей.

Низкая доставка Mosquitto в QoS 1 сохранена явно. Использован существующий профиль: у точки payload 16 байт, QoS 1, N=16 условная недоставка равна 0,9124559971701972; модель применяет её и при малой предложенной нагрузке. Повторные стадии пересылки могут дополнительно сокращать доставку. Выборка из 20 публикаций не годится для оценки точности или предельной производительности. У QoS 0 той же точки исходный параметр недоставки равен нулю; проверены реальные доставки удалённым модельным получателям. Профиль для улучшения результата не менялся.

Границы: `MemoryMax=2G`, swap 0, `CPUQuota=150%`, одно задание одновременно, резерв диска 10 ГиБ, бюджет данных 5 ГиБ. CPU/RSS относятся к вычисляющему процессу, а не к реальному MQTT-брокеру. Натурные измерения выполняет MqttBenchmark отдельно от Web; MqttY исполняет модели.

Подробные receipts содержат запросы, статусы, PID, manifest, summaries и результаты проверки seals. `service-receipt.json` содержит unit, PID службы и Web, хэши релиза, профилей и условия запуска. Для доступа используйте SSH-туннель: `ssh -N -L 5088:127.0.0.1:5088 <пользователь>@<хост>`; затем откройте `http://127.0.0.1:5088`.
