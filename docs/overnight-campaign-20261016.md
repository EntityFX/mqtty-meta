Порядок для каждого брокера: калибровка → профиль → Fidelity → новые независимые
замеры → контрольные симуляции → Relay. Сначала отдельные pilots четырёх брокеров;
после четырёх полных циклов — mixed. Native последовательны; симуляции до четырёх
независимых процессов с последовательным refresh внутри. Перекрытия native/simulation нет.

Только capture envelope успешных native: `576 × 39 / 3600 = 6,24 ч`.
Дополнительно нужны startup/preflight, ZIP, повторная агрегация и симуляции.
Ориентир всей серии 10–13 часов предварительный: N=64/128 новой модели не проходили
полную проверку длительности. Полное покрытие к 08:00 не гарантируется; deadline
приоритетнее, незавершённые этапы показываются явно, артефакты сохраняются.

Модель MqttY зафиксирована на `f61daa47ec581ff88f20ee70882722085d1a0a10`.
До серии 12 сценариев двух точек Mosquitto N=1 воспроизведены на Windows и Linux
с одинаковыми scientific summaries, без провалов критериев. Это регрессия по уже
изученным observations, не полный тест новой модели и не новый слепой контроль.
Ночная validation собирается после фиксации профиля; профиль и пороги не меняются.
RPS ≤15%, p99 ≤20%, |Δfailure/loss| ≤0,05 сохраняются; провалы не останавливают покрытие.

Все raw, ZIP, restoration scratch, runtime и источники находятся на hd250.
Минимум свободного места: hd250 20 GiB, системный диск 10 GiB; mount/device/ext4
проверяются перед нагрузкой и очисткой. Удаляется только проверенный restoration scratch.
Брокер CPU 0; контроллер 1–11,13–23, sibling 12 исключён. Лимиты broker/controller
4/8 GiB, симуляциям резервируется 1,25 GiB на процесс, рабочий предел 6 GiB.
