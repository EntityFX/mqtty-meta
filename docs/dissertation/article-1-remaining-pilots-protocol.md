# Пилоты остальных брокеров для статьи 1

**Цель:** проверить исполнение и наблюдаемость Aedes, ActiveMQ и EMQX до новой калибровки и контроля. Завершённый Mosquitto повторно не измеряется. Эти пилоты не входят в основную программу из 40 запусков.

**Программа:** последовательно Aedes → ActiveMQ → EMQX; для каждого окна подачи 2 и 4 с. Всего шесть натурных и шесть соответствующих модельных опытов. Условия: 16 отправителей, один получатель, 16 байт, QoS 1, seed 42; прогрев 1 с, после прекращения подачи наблюдать ещё 5 с. Tick модели — 10 мкс; нагрузка и наблюдение составляют 200 000/400 000 и 500 000 тиков. Подключение и подписка добавляют свои тики.

Натурную часть исполняет сохранённый TwinValidationProbe с MqttBenchmark, брокер — отдельный процесс. Модель ставится через `POST /api/twin-validations` в очередь Linux Web. Используются прежние профили только для проверки пути и журналов, а не для утверждения новой точности. SHA профиля Web должен совпасть с выбранным неизменяемым входом. Отсутствующая точка не заменяется соседней.

Полные данные: отдельный каталог `article1-matched-remaining-pilots-v1` на диске доказательств. Каждая попытка получает новый каталог, конфигурации, прогресс, ID Web-задания, первичные журналы, пересчёт и SHA. Прежние попытки, профили и runtime не изменяются. В Git — программа, launcher, тесты и компактные квитанции.

## Допуск и ограничения

- До старта проверить mount, запас диска, SHA сохранённого runtime, профилей, бинарных файлов брокеров и их конфигураций. В момент натурного измерения другие задания Web не должны выполняться или ожидать запуска; обнаруженное пересечение блокирует продолжение.
- Брокер использует логический CPU 0, натурный измеритель — 2–3, как в существующем пилоте. Не менять конфигурацию исходного брокера; временные адреса и каталоги задаются в собственной копии. EMQX считается готовым после MQTT CONNACK, одного открытого TCP-порта недостаточно.
- Пилот технически принимается только при подтверждённых фазах, подписках и непрерывно наблюдаемом соединении подписчика; нужны завершённые измерительные публикации и отсутствие pending ID. Прогрев отделяется по ID, метрики пересчитываются из raw по общей границе наблюдения.
- Расхождение с прежним профилем сохраняется, но не подменяет технический отказ. Старые допуски 15% / 20% / 0,05 / 0,05 не меняются. Не повторять опыт до получения удобного результата.
- При разрыве, недостающем журнале, техническом отказе или пересечении с чужой нагрузкой сохранить причину и остановить расширение. После устранения подтверждённой причины продолжать только ещё не готовые точки отдельной попыткой с тем же общим бюджетом; автоматических повторов нет.
- Текущий launcher выполняет только первую попытку. Процедура продолжения недостающих точек должна быть подготовлена отдельно после разбора причины; повторный вызов той же команды не является resume и не перезаписывает готовые результаты. Сохранённый budget.json не допускает сброса срока.
- Внутренний общий бюджет — **900 с**, systemd — до **960 с** с резервом на остановку. Модельное задание — максимум 230 с в пределах остатка; ожидание очереди входит в бюджет launcher. На завершение чужих заданий не ждать бесконечно. После истечения бюджета не начинать недостающие точки под новым deadline.
- Основная серия остаётся недопущенной. После пилотов ещё нужны проверка разрыва/восстановления, известные ID, влияние регистрации на измеритель и прогноз всей шестичасовой программы. Только затем — новая калибровка и отдельно зафиксированный контроль.
