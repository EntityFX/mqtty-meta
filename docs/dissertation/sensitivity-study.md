# Проверка чувствительности двойников к шагу времени и окну нагрузки

Это дополнительный модельный опыт для первой статьи. Он проверяет устойчивость результата к численным настройкам. Статью пишет человек; агент предоставляет программу, результаты и графики. Профили по новым результатам не подбираются, независимым натурным контролем этот опыт не является.

## Программа

| Параметр | Значение |
| --- | --- |
| Брокеры | Aedes, Mosquitto, ActiveMQ, EMQX |
| Payload | 16 байт; вывод не распространяется автоматически на 256 байт |
| Publishers | 1 и 128 — крайние доступные точки |
| QoS | 0, 1, 2 |
| Seed | 42, 43, 44 |
| Опорный режим | Tick 10 мкс, нагрузка 2 с |
| Меньший шаг | Tick 5 мкс, нагрузка 2 с |
| Более длинное окно | Tick 10 мкс, нагрузка 4 с |
| Прогрев / drain | 1 с / до 5 с во всех вариантах |
| Основная матрица | 4 × 2 × 3 × 3 × 3 = **216 симуляций** |
| Повторы сохранённых конфигов | **6 симуляций** |
| Предварительные pilots | **8**, отдельно от 222 основных проверок |

Offered RPS, профиль, контрольные наблюдения, seed и сеть одной точки остаются прежними. При уменьшении tick удваиваются значения warmup/measurement/drain, outgoing wait, transfer и throughput window, заданные в тиках. Это сохраняет их физические длительности; меняется разрешение дискретизации. Автоматическое разрешение транспорта по эмпирическому RTT выполняется прежним замороженным алгоритмом. Очередь, скорость линка и профиль не подбираются по новым исходам.

Pilots — опорные QoS 1 / seed 42 для каждого брокера и обоих чисел publishers. Их конфиги совпадают с соответствующими опорными условиями, но выходы сохраняются отдельно и в 216 не засчитываются. Они проверяют повторение прежнего результата, время и память до запуска полной матрицы. Программа фиксируется до pilots.

## Контроль корректности

- Используется прежний CLI кампании и его зависимости, скопированные в отдельный snapshot. Профили и observations также копируются с сохранением SHA-256.
- Каждая опорная симуляция должна совпасть с сохранённым scientific summary основной кампании. Несовпадение останавливает дальнейшие запуски как техническую проблему; профиль и пороги для обхода проверки не меняются.
- Код 3 CLI означает failed критерий точности при завершившейся симуляции. Это сохраняемый научный результат. Технические ошибки CLI, timeout, превышение памяти и незавершённая фаза выделяются отдельно и останавливают pipeline.
- У шести повторов проверяются точные хэши summary и гистограммы, а также канонических научных счётчиков брокеров и receivers. Системные время/PID/память не считаются детерминированными выходами.
- Пороги не изменены: RPS 15%, p99 QoS 1/2 20%, абсолютная разность failure/loss 0,05. QoS 0 ACK неприменим.
- Успех опорного воспроизведения не доказывает точность модели. По-прежнему показываются все failed/notApplicable, критерии и исходные значения.

## Запуск и хранение

Скрипт `tools/dissertation/sensitivity_campaign.py` использует стандартную библиотеку Python и существующий .NET runtime. Команды подготовки и выполнения разделены:

```text
python sensitivity_campaign.py prepare --controller /path/to/completed/controller --models /path/to/frozen/model-evidence.json --output /path/to/evidence/new-study --mount-root /path/to/evidence
python /path/to/evidence/new-study/inputs/sensitivity_campaign.py run --plan /path/to/evidence/new-study/plan.json --mount-root /path/to/evidence --workers 2 --dotnet /path/to/dotnet
```

Controller — завершённая кампания с исходными JSON-конфигами; model-evidence — её опубликованные научные результаты. Новое размещение выходов не изменяет эту кампанию. Выход должен находиться на явно смонтированном диске доказательств; требуется не менее 5 ГиБ свободно. Raw и полные выходы хранятся вне Git.

Работают не более двух моделей одновременно. Сохраняются peak RSS, wall time, PID активных процессов, лог и запись каждой попытки. Лимит отдельного запуска — 30 минут и 3 ГиБ RSS; общий процесс дополнительно ограничивается службой. Это технические пределы, а не критерии качества брокера.

`progress.json` показывает отдельно pilot/matrix/replay, failed критерии и технические ошибки. После восьми pilots появляется ориентир времени всей матрицы; экстраполяция стоимости QoS 1 на другие QoS приблизительна. Она не является гарантированным сроком. `results.json` создаётся перед итоговым статусом completed.

Для возобновления прерванного совместимого запуска укажите `--resume`. Код и входы проверяются по хэшам; сохранённые попытки не стираются. После технического отказа автоматический retry запрещён: сначала нужно установить причину и сохранить решение. При смене кода/входов создаётся новая версия опыта.

На Linux pipeline запускается отдельной пользовательской службой systemd с ограничением памяти и журналами на диске доказательств. После подтверждения старта агент сохраняет состояние и приостанавливает цель до ручного продолжения. Сам расчёт работает независимо от SSH.
