# Почему пересылка заканчивается и когда сообщение доходит всем

Материал для статьи 2 и главы 3. Здесь доказываются свойства заданной модели пересылки, а не натурной системы брокеров. Новых MQTT-опытов нет. Основной текст диссертации и исполняемый снимок Linux не менялись.

## Что именно рассматривается

Есть N брокеров и связный простой неориентированный граф соседства с m рёбрами. Каждое ребро допускает отправку в обе стороны. Рассматривается один ID «источник, последовательный номер», первоначально полученный только брокером-источником. Этот граф — логические соседи федерации; промежуточные сетевые узлы без брокера не входят в N.

[StaticFederator](../../mqtty/src/EntityFX.MqttSimulator/EntityFX.MqttY.Federation.App/Federation/StaticFederator.cs) сначала проверяет кэш ID и при первом получении сохраняет запись. Затем ставит локальную доставку и пересылки в очереди. [FloodingPolicy](../../mqtty/src/EntityFX.MqttSimulator/EntityFX.MqttY.Federation.App/Federation/FloodingPolicy.cs) исключает из соседей отправителя. Повторный ID не доставляется и не пересылается; его остаток переходов не заменяет сохранённое первое получение. Кэш не очищается в ходе опыта. Это существенная часть условий доказательства.

Обозначим через H исходный лимит переходов. При получении на глубине d первого пути остаётся H−d. Если остаток нулевой, локальная доставка всё ещё ставится в очередь, но дальнейшие отправки запрещены. За каждое запрещённое направление увеличивается счётчик исчерпаний, даже если сосед уже получил другой экземпляр.

## 1. Конечность прикладной пересылки

Для фиксированного ID каждый узел проходит обработку первого получения не более одного раза. При ней он пытается поставить не более одной пересылки на каждого соседа. Сумма степеней равна 2m, поэтому число порождённых постановок на межброкерную пересылку не превышает **2m**. Локальная доставка ставится не более одного раза на брокере с подписчиком.

Это граница прикладных операций федератора. Она не ограничивает сама по себе число TCP-пакетов, протокольных повторов, длительность незавершившегося обмена или физические переходы каждого пакета. Для окончания расчёта нужны также завершение/отказ операций и технический предел ожидания. Переполнение очереди уменьшает фактическое число выполненных публикаций, но не создаёт новый цикл обработки ID.

Условие сохранённого кэша обязательно. В приложении переполнение кэша вызывает техническое исключение; защита не отключается молча. Удаление старых ID потребовало бы нового доказательства.

## 2. Достаточный лимит для получения всеми брокерами

Предположим дополнительно: исходное сообщение дошло до федератора; очередь не теряет постановки; отправленные экземпляры успешно поступают соседям; локальные доставки завершаются; обработка продолжается достаточно долго. Отказов соединений, изменения графа и потерь здесь нет.

У каждого впервые получившего ID неисточника есть родитель — узел, отправивший первое принятое сообщение. Родитель получил ID раньше своего потомка. Следовательно, родительские связи образуют дерево первого получения, а глубина любого обработанного узла не превосходит N−1.

Для полной доставки достаточно **H≥N−1**. Докажем от противного. Пусть после завершения всех отправок множество S уже получивших брокеров не охватывает граф. Из связности есть ребро от узла v из S к ещё не получившему u. Путь первого получения v целиком лежит в S, поэтому имеет длину не более |S|−1≤N−2. Остаток переходов у v не меньше одного. Узел u не является родителем v, поскольку ещё не получал ID. Значит, v должен отправить ему экземпляр, а тот по условиям будет получен. Получилось противоречие.

Это достаточная граница для любого порядка обработки при данных условиях; она не заявляется минимальной для каждой конкретной топологии. Для подписчиков полнота дополнительно требует успешного локального MQTT-обмена. Если подписчиков нет, все узлы всё ещё могут обработать ID, но показатель полноты пар с нулевым знаменателем неприменим.

## 3. Когда получается точная формула числа пересылок

Для равенства, а не только полной доставки, удобно более сильное условие **H≥N**. Даже узел на глубине N−1 тогда имеет хотя бы один оставшийся переход и не обрезает выходы по лимиту. Источник отправляет всем своим соседям; каждый из N−1 остальных узлов исключает ровно одного родителя.

Поэтому для одной публикации число межброкерных экспортов:

**F = 2m − (N−1).**

Для A₀ разных ID, успешно поступивших исходным федераторам, при тех же условиях сумма равна **A₀[2m−(N−1)]**. A₀ совпадает с числом API-попыток A только если все эти исходные попытки действительно поступили в обработку. При потерях источника автоматически подставлять A нельзя.

Если каждый экспорт доставляется федератору ровно один раз и нет дополнительных повторных исходных получений, N−1 прибытий являются первыми, остальные подавлены: **повторов = F−(N−1)** на ID. При дополнительных повторных MQTT-получениях этот последний счётчик может быть больше, хотя новых прикладных экспортов они не порождают.

Для дерева m=N−1: F=N−1. Для кольца N≥3: m=N, F=N+1. Для полного графа m=N(N−1)/2: F=(N−1)². Это разные формулы для разных графов, а не свойство названия «федерация» вообще.

У Relay в рассматриваемой реализации источник экспортирует ID каждому из N−1 удалённых брокеров; импорт не попадает в экспортную тему. При успешной доставке источника и всех выходов **F=N−1**. Возвращённый импорт не запускает новый круг. [Темы](../../mqtty/src/EntityFX.MqttSimulator/EntityFX.MqttY.Federation.App/Federation/FederationTopics.cs) и [MqttRelay](../../mqtty/src/EntityFX.MqttSimulator/EntityFX.MqttY.Plugin.Mqtt/Application/Mqtt/MqttRelay.cs) — часть этого условия. Смешивание входных/импортных тем потребовало бы повторной проверки.

## 4. Почему одного диаметра недостаточно

Контрпример: рёбра 0–1, 0–2, 1–2, 2–3. Диаметр равен двум. Источник 0 начинает с H=2. Допустим такой порядок обработки: 0; затем экземпляр 0→1; затем 1→2; затем задержавшийся 0→2.

Узел 2 впервые получает ID через 1 с нулевым остатком. Он запоминает ID и не пересылает узлу 3. Более короткая копия 0→2 имеет больший остаток, но подавляется как повторная. Узел 3 не получает сообщение, хотя расстояние от источника до него равно двум.

Это допустимая абстрактная последовательность доставок при разных временах ожидания выходов, не утверждение, что именно она наблюдалась в Linux-кампании. Лимит H=N, используемый по умолчанию, избегает данного ограничения при прочих идеальных условиях. Изменение логики выбора первой копии в текущей работе не предлагается.

Другой пример: полный граф из четырёх узлов, H=3. При первых получениях по пути 0→1→2→3 все узлы получают ID, но последний не выполняет два дальнейших экспорта. Получается F=7 вместо 9 и два исчерпания лимита. Следовательно, **исчерпание лимита не всегда означает недоставку**, а H=N−1 для полной доставки ещё не гарантирует точную формулу всех экспортов.

## 5. Как это проверено

Сначала написаны четыре проверки с известным ответом; до реализации модуля получен RED из-за отсутствия проверяющего кода, затем все четыре прошли. Независимый малый перебор [в Python](../../tools/dissertation/verify_forwarding_properties.py) рассматривает все порядки обработки сообщений одного ID: **44 связных размеченных графа**, **167 сочетаний графа и источника**, лимиты N−1 и N, **15 005 состояний**, **401 конечная проверка**. Все укладываются в доказанные условия. Максимальный размер — четыре узла; тесты не заменяют доказательства для произвольного N.

Перебор не моделирует MQTT-пакеты, очередь с ограничением ёмкости, модельное время или физическую сеть. Его роль — проверить логику доказательства на малых примерах, включая два контрпримера выше. Наличие Python-проверки не доказывает автоматически корректность всей C#-реализации: с кодом вручную сверены порядок кэша, исключение отправителя и проверка H.

Дополнительно формулы сверены с шестью полными условиями доступной основной серии, по три seed в каждом. При 10 000 публикациях Relay имеет 30 000 экспортов; федерация в линии — 30 000, в кольце — 50 000. При 50 000 публикациях соответствующие числа возрастают в пять раз. Перегруженные точки с потерями не использованы как случаи точного равенства.

[Квитанция](../../reports/audits/dissertation/network-formal-properties-v1/verification.json) содержит SHA исходников и входных результатов. Команды:

```text
python -m unittest discover -s tools/dissertation -p test_forwarding_properties.py -v
python tools/dissertation/verify_forwarding_properties.py --output <новый-каталог> --stats reports/audits/dissertation/network-main-recount-v1/condition-stats.json
```

Логические экспорты не равны физическим переходам: прямое MQTT-соединение Relay может проходить несколько сетевых сегментов. Поэтому формула F сама по себе не ранжирует полный сетевой трафик, задержку или аппаратную эффективность.
