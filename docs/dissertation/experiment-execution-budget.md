# Ограниченный порядок экспериментальной работы

Цель — получать проверяемые результаты без бесконечной последовательности диагностик. Правило действует для новых работ; замороженные серии и их входы не меняет.

## До запуска

1. Проверить существующие результаты и повторно использовать уже проверенные измерения. Не пересчитывать опыт ради исправления индекса или отчёта.
2. Записать один конкретный вопрос, ожидаемые исходы и действие для каждого исхода. Если исход ничего не изменит, опыт не запускать.
3. Разделять отказ процесса, неполный drain, перегрузку очереди и непрохождение точности. Научный отрицательный результат не требует автоматического retry.
4. Одна короткая проверка механизма после изменения кода. Для следующего большого запуска заранее оценить время, RAM, объём результатов и запас drain по известным данным. Короткий smoke не заменяет научную матрицу.

## Бюджет диагностики

- Не более двух новых диагностических вариантов на одну гипотезу без нового факта. Если объяснения нет — сохранить blocker, предложить варианты и согласовать изменение программы вместо новых догадок.
- Не менять одновременно несколько факторов. Каждая попытка имеет отдельный каталог, причину, SHA и лимиты.
- Для долгого опыта сохранять частичные доказательства. Автоматический повтор допустим только для явно распознанного временного инфраструктурного отказа, максимум один раз и отдельной попыткой; изменение модели, входов или критериев автоматически не разрешается.
- После доказанного исправления выполнять предусмотренное покрытие пакетно с checkpoint/resume. Перед основной матрицей сохранить предусмотренное программой решение по pilots; диагностики не выдавать за допуск.

## Минимум участия агента

- Монитор/контроллер следит за процессом без участия языковой модели. Агент читает один краткий snapshot по запросу или на контрольной точке.
- Не выводить целиком progress.json, histograms или raw. Извлекать только статус, этап, completed/total, категории ошибок, elapsed, RSS, диск, ETA и краткую причину. Рабочая сводка — до 8 КиБ; большие данные остаются файлами.
- Одна проверка PID после запуска. Пока расчёт идёт, агент делает независимую работу; если её нет, завершает ход. Никаких циклов ожидания и новых таймеров.
- Обновление Progress.md — по смене этапа, результату проверки или запросу пользователя. Процент считать по принятым шагам; число диагностик его не повышает.
