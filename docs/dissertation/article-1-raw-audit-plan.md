# План фонового аудита первичных журналов статьи 1

**Цель:** проверить все 48 натурных и 48 модельных результатов по сохранённым событиям и определить, оставался ли подписчик подключён во время измерения.

**Подход:** отдельный проверяющий процесс читает финальную сводку, пересчитывает показатели существующим `audit_twin_cohort.py`, сверяет SHA-256 и исследует события соединений. Научный runtime не запускается. Результаты пишутся только в новый каталог доказательств.

**Навыки:** writing-plans — декомпозиция и критерии; systematic-debugging — наблюдение до исправления; verification-before-completion — тесты и подтверждение службы. Выполнение непосредственно текущим агентом разрешено пользователем; повторное согласование запуска не требуется.

## Ограничения

- Старые опыты, профили, runtime и критерии не изменять.
- Предельное время фонового аудита — 30 минут, память — 2 ГиБ, один CPU, без swap.
- При отсутствии диска доказательств не переходить на системный диск.
- Сохранённые данные после записи не перезаписывать; техническую причину отказа записать отдельно.
- Прохождение проверки соединений не означает правильность всех MQTT-обменов; отсутствие событий не считать подтверждённым соединением.
- Прежняя сетевая кампания исчерпала общий deadline. Его не сбрасывать под видом resume.
