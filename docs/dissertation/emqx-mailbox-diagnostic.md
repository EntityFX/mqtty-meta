# Короткая проверка отключения получателя EMQX

## Вопрос и имеющиеся доказательства

В трёх сохранённых опытах EMQX / QoS 1 / 128 отправителей подписчик отключён до измерения. В журналах брокера есть `check_oom_shutdown` с причиной `mailbox_overflow`: предел 1000, наблюдаемые значения 1333, 1168 и 1193. Это внутренняя очередь процесса Erlang, а не MQTT-очередь недоставленных сообщений и не доказательство нехватки всей RAM компьютера.

Гипотеза: закрытие соединения связано с ограничением этой очереди. Причина её накопления отдельно не установлена. Для проверки выполняются ровно два коротких диагностических опыта, без повторения матрицы.

## Сравнение

| Параметр | Контроль | Диагностический вариант |
| --- | --- | --- |
| EMQX, измеритель | Прежние замороженные бинарные файлы | Те же файлы |
| Получатели / отправители | 1 / 128 | 1 / 128 |
| Payload / QoS | 16 байт / 1 | 16 байт / 1 |
| Прогрев / нагрузка / ожидание | 1 с / 2 с / до 5 с по прежней политике | То же |
| CPU брокера / генератора | 0 / 1,2 | То же |
| max_mailbox_size | 1000 | 5000 |
| Защита force_shutdown | Включена | Включена |

Контроллер создаёт два новых каталога и отдельные копии брокера. Сначала проверяет фактически применённую настройку через CLI брокера. При отсутствии подтверждения настройки опыт не начинается. Прежняя серия, профили и результаты не изменяются.

Общий предел — 10 минут, память службы — 2 ГиБ, максимум три CPU. Каждый брокер запускается последовательно; завершаются только принадлежащие контроллеру процессы. Автоматических повторов после отказа нет.

## Что проверять

- Состояние подписчика от начала до конца измерения, время разрывов и повторных подключений.
- Записи `mailbox_overflow` и фактическую длину очереди при срабатывании защиты.
- Исходы публикаций, уникальные получения, недоставку и фазу получения.
- Совпадение бинарных контрольных сумм и различие только объявленного параметра.

Если контроль не воспроизведёт разрыв, это ограничение новой проверки; старые журналы не опровергнуты. Если увеличение очереди уберёт разрыв, это поддержит роль ограничения, но не установит, почему очередь росла и как надо настраивать промышленную систему. Если разрыв сохранится, проверяются точная причина и новый порог; третий вариант без нового факта не запускается.

Эти два результата не входят в сравнение точности модели: изменённая конфигурация брокера требует отдельного профиля и программы проверки. Допуски статьи не меняются.
