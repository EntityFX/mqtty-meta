# Проверенная основа для двух статей и диссертации

Цель этого блока — связать первичные измерения, параметры двойников и опубликованные числа. Он завершает техническую часть шагов 03–06. Это не новые эксперименты и не утверждение, что все двойники точны.

## Что фиксируется

| Файл в `reports/audits/dissertation/foundation-v2` | Что он содержит |
| --- | --- |
| `manifest.json` | Версии репозиториев, SHA-256 файлов пакета, идентичность полного пересчёта |
| `input-registry.json` | SHA-256 входов, четыре профиля, отдельные идентичности калибровки и контроля, ограничения и критерии |
| `metrics-verification.json` | Независимая проверка арифметики, CI, критериев точности, EST и сохранённых повторов |
| `native-coverage.csv` | Все 592 архива: выбранные измерения, pilots, отклонённые попытки и доступность журналов |

Полный первичный пересчёт `audit-results.json` хранится на диске доказательств. В Git входят компактный итог и таблица покрытия; ZIP/TAR и первичные архивы туда не добавляются. Редакционные изменения документации не изменяют исходные campaign identities.

## Кто что делает

1. **MqttBenchmark** ранее запустил реальных клиентов и брокеры, сохранил журналы, guard и телеметрию. В этом блоке нагрузка не повторяется.
2. **MqttY** ранее построил профили и выполнил модельные опыты. Профиль при независимом контроле не изменяется.
3. **`run_native_audit.py`** читает архивы без распаковки, проверяет seals, ID, счётчики, временные знаменатели и доступные квантили. Он работает отдельно от приложения измерений.
4. **`foundation.py`** связывает полный пересчёт с выбранными результатами и профилями, повторяет опубликованную арифметику и создаёт версионированный реестр входов.
5. **Автор и независимый сотрудник** оценивают пригодность научных выводов, разбирают причины, повторяют выбранные расчёты и принимают текст. Автоматическая проверка это не заменяет.

## Проверить сохранённую основу на другой машине

Опубликованная версия основы — `foundation-v2`. Пробная сборка v1 обнаружила неполный набор зависимостей при переносе на Linux; её snapshot сохранён вне Git как технически не принятый. Данные измерений при исправлении пакета не изменялись.

Нужны Git с подмодулями и Python 3.10 или новее. Команды выполняются из корня мета-репозитория. Пакеты Python для этой проверки не требуются.

```text
git submodule update --init --recursive
python -m unittest discover -s tools/dissertation -p "test_*.py" -v
python tools/dissertation/foundation.py verify --manifest reports/audits/dissertation/foundation-v2/manifest.json
```

Проверка сверяет файлы с зафиксированными хэшами и заново считает арифметику. При сравнении вычисленных вещественных значений между версиями Python допускается только округление: относительный и абсолютный допуск 10⁻¹⁰. Счётчики, состав полей и решения passed/failed должны совпадать точно. Это не изменение порогов точности двойников. Она не обращается к брокерам и не проверяет ещё раз события в недоступных первичных архивах. В JSON-ответе `fullRawAuditVerified=false` означает именно отсутствие проверки полного файла пересчёта на этой машине.

Чтобы дополнительно проверить полученную с диска доказательств полную сводку, передайте фактический путь:

```text
python tools/dissertation/foundation.py verify --manifest reports/audits/dissertation/foundation-v2/manifest.json --native-audit /path/to/evidence/full/audit-results.json
```

Путь может быть Windows- или Linux-путём. Сверяются SHA-256 полной сводки и связь каждой строки с реестром архивов и опубликованным измерением. Это проверка сохранённого пересчёта; для нового чтения самих событий нужен следующий раздел.

## Повторить пересчёт первичных событий

На Linux нужен смонтированный диск доказательств. Из сохранённого каталога предыдущего аудита возьмите `inputs/archive-registry.json`, `inputs/native-evidence.json`, `inputs/native_audit.py` и `inputs/run_native_audit.py`. Если содержимое этих двух Python-файлов отличается от текущей версии, для повторения используйте сохранённые файлы. Полные имена архивов в реестре должны указывать на реально доступные копии с теми же SHA-256; при смене расположения создайте отдельный реестр и отдельный аудит, сохранив прежний.

```text
python /path/to/saved/inputs/run_native_audit.py --registry /path/to/saved/inputs/archive-registry.json --native-evidence /path/to/saved/inputs/native-evidence.json --output /path/to/evidence/new-audit --mount-root /path/to/evidence --workers 2
```

`--mount-root` — сама точка монтирования; output и архивы должны находиться внутри неё. Скрипт требует не менее 5 ГиБ свободного места. Новое имя output исключает перезапись; для прерванного совместимого запуска используется `--resume`. Продолжение проверяет прежние хэши кода и входов. Ошибка не является основанием очищать raw.

Ожидаемый результат существующего набора: 592 обработанных архива, 576 подтверждённых выбранных измерений, 12 успешных pilots вне основной матрицы и 4 отклонённые попытки; технических ошибок и расхождений выбранных результатов нет. Для двух отклонённых EMQX-попыток журналы публикаций/доставок отсутствуют: повторный пересчёт их не восстанавливает.

После новой проверки другой сотрудник сравнивает показатели по соответствующим архивам и исходным идентичностям. Монотонная длительность самого аудита, PID и порядок завершения workers не являются научными результатами и могут отличаться.

## Создать следующую версию основы

После изменения методики или входов прежний пакет сохраняется. Сначала проверьте тесты и научный смысл изменения; затем создайте новый каталог:

```text
python tools/dissertation/foundation.py freeze --output reports/audits/dissertation/foundation-v3 --native-audit /path/to/evidence/full/audit-results.json
```

Эта команда не меняет наблюдения, профили и результаты кампании. Она требует полный согласованный аудит, сверяет его с сохранённым заключением Linux и пересчитывает арифметику. Если изменились исходники первичного верификатора или входы, нужен соответствующий новый аудит и его явно зафиксированное заключение. Изменённый файл не объявляется совместимым только потому, что итоговое число похоже на прежнее.

## Границы принятия

- Совпадение пересчёта подтверждает вычисления по доступным журналам, но не отсутствие систематической ошибки стенда.
- Высокий EST не является вероятностью истинности или точностью модели; QoS 0 EST* отличается от строгой четырёхкомпонентной формулы.
- Сетевые опыты Relay/федерации не получают натурной точности из проверки одиночного брокера. Короткие опыты проверяют механизм, а не установившуюся предельную производительность.
- Выбранные same-seed повторы не заменяют независимого повторения на другой машине и человеческого рецензирования.
- Формулы и знаменатели фиксируются технически. Окончательное научное принятие и защищаемые утверждения в manifest остаются `pending` до решения автора и руководителя.
