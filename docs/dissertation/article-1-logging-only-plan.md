# План: отключение только записи событий и завершение серии статьи 1

**Цель:** отдельно измерить влияние записи публикаций и получений, сохранив прежние нагрузку, ID, подписки, учёт и фазы; затем выполнить уже предусмотренную программу 40 запусков.

**Архитектура:** `CampaignDefinition.WriteMessageEventLogs=true` сохраняет прежнее поведение. Значение false отключает только `publishes.ndjson` / `deliveries.ndjson`; фазовые часы, соединения, подписки, DeliveryLedger и итоговые показатели остаются активны. Отключение разрешено только для явно заданного cohort-режима с полным сроком наблюдения. Отсутствующие журналы обозначаются в phases.json.

**Технологии:** C#/.NET 6, MSTest, существующий MqttCampaignRunner; Python для ограниченного запуска. Основание — [готовность к калибровке](article-1-calibration-readiness-plan.md). SUPERPOWERS writing-plans / test-driven-development / verification-before-completion: тест, проверка отказа, минимальное изменение, проверка результата.

- [x] Добавить `MessageEventLoggingTests.cs`: оба режима проходят настоящие MQTT-соединения локального брокера, сохраняют прогрев, точное окно, полный drain, все подтверждённые подписки и исходы. Фактические ID на сервере совпадают с вычисленными ID и счётчиками; без записи нет выдуманных raw.
- [x] В `CampaignDefinition.cs` добавить явный флаг с прежним значением по умолчанию и ограничением диагностического режима.
- [x] В `CampaignWorkloadRunner.cs` менять только создание/вызов двух файловых журналов. В `WorkloadPhaseRecorder.cs` сохранять объявленный режим. Прогнать новые тесты и регрессию измерителя.
- [x] В исходниках нового TwinValidationProbe передать флаг; добавить явное измерение RTT существующим протокольным preflight для новой калибровки. Старые замороженные исполняемые файлы не заменять. Сохранить настоящий preflight и его RTT, не подставлять прежний.
- [x] До измерений зафиксировать ABBA: ActiveMQ, запись on/off/off/on, по одному новому процессу брокера; 16 байт, QoS 1, 16 отправителей, 1 subscriber, прогрев 1 с, подача 4 с, наблюдение 5 с. Общий срок не более 900 с, без автоповторов и сброса deadline. Старые готовые пилоты и диагностика не повторяются.
- [x] Сохранить каждую попытку; сравнить RPS, p99 и недоставку описательно. Это суммарное влияние создания/сериализации/очереди/вывода файлов сообщений, а не изолированная скорость диска. Соединения и фазовые файлы сохраняются в обоих вариантах. Без файлов ID невозможен независимый пересчёт raw — явно указать ограничение.
- [x] После технической проверки зафиксировать окно и новый runtime, оформить допуск и запустить программу 12 калибровочных + 12 контрольных + 12 моделей + 4 повторов, общий предел шесть часов. Сохранять отрицательные точностные результаты; модель по контролю не настраивать.

Главная серия использует запись on. Живой Linux Web и прежние результаты не меняются; модели через прямой новый Probe допустимы как объявленное исключение, если живой Web ещё не поддерживает новый профиль. При запуске долгого расчёта подтвердить службу и progress, обновить отчёты и остановиться для ожидания.

Серия 40 запущена после зафиксированного допуска: [квитанция](../../reports/audits/dissertation/article-1-main-execution-v1/launch.json). Завершение самой серии здесь не заявляется.
