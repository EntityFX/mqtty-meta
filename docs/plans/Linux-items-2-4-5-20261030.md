# Пункты2,4,5 Linux-очереди — Implementation Plan

**Goal:** выполнить отдельные короткие проверки ядра, основной сетевой точки и устойчивости прежних профилей во времени.

**Architecture:** три разделённых протокола и один последовательный ограниченный controller. Ни benchmarks, ни натурные брокеры не работают одновременно. Исторические источники читаются; новые бинарные файлы и результаты находятся вне прежних каталогов.

**Tech Stack:** .NET6 probe, Python stdlib, GNU time, Linux systemd/cgroup.

**Spec:** [пункты2,4,5](../../reports/status/Linux-work-queue.md).

## Пункт2: один граф

- Отдельный GraphExecutionProbe использует классы текущего MqttY f5c0a47. Копия FederationRunner автоматически преобразуется только переименованием класса, добавлением аргумента parallel и заменой Refresh(false,0) на Refresh(parallel,0). Преобразование проверяется тестом; исходный runner не меняется.
- Один маленький фиксированный q1024 fixture:4 брокера,64 publishers,4 receivers,QoS2,r1000,seed42,tick0,1мс; окна0,01/0,05/1с. Сначала проверка serial probe против исходного serial runtime; затем parallel. Это feasibility/equivalence, не устойчивый speedup на всех нагрузках.
- Все шесть scientific файлов и пересчёт обязательны; любое расхождение сохраняется, ускорение не принимается. CPU/память/wall записываются. На job120с, весь подпункт420с.

## Пункт4: исходная основная точка

- Frozen network runtime12601f5 и конфиг matrix.star.federation.q2.r5000.w10.s42.json без сокращения фаз. A:очередь1024; B:4096. Только queueCapacity меняется; network.queue и остальные параметры сохранены.
- Относительное расписание/ID проверяются, абсолютные timestamps могут измениться из-за warmupDrain. Не объявлять одинаковый входной payload побайтно до проверки.
- Это одна выбранная точка, не причинный разбор всех162. QueueDrops — события enqueue, не число потерянных сообщений. При техническом отказе не утверждать причинный эффект. На job240с, весь подпункт600с.

## Пункт5: другая натурная сессия

- Aedes,Mosquitto,ActiveMQ,EMQX; по3 новых native повтора,16Б,QoS1,16pub,1sub,seed42/43/44;1/4/5с,логированиеon,тот же frozen Probe и broker configurations, fresh broker per repeat,CPU0 и2–3.
- Старые четыре профиля и их SHA фиксируются до опыта, не перекалибровываются. Новые12 моделей запускаются со старыми профилями и новым контролем; имена кампаний явно другие. Сохраняется прежняя closed-loop политика Probe, включая высокий токеновый предел publishers/tick; новая измеренная скорость не подставляется вместо него. Это временная устойчивость на той же нагрузочной политике, не переносимость аппаратуры.
- Сравнить исходные/новые native агрегаты и новые model/native; прежние допуски15%/20%/0,05/0,05. Не требовать прохождения для сохранения результатов. По3 модельных seeds на брокер; без выбора лучшего.
- При техническом отказе брокера сохранить попытку и перейти к другому брокеру; не пытаться повторно запускать ту же точку автоматически. Модель для неполного3-repeat контроля не допускается.
- Весь подпункт1800с; native readiness70с/job, модель120с/job. Не доказывает переносимость на другое оборудование.
