# Отдельный натурный контроль в Web

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Выбирать сохранённый отдельный натурный контроль, связывать его с профилем и видеть проверяемое сравнение в браузере.

**Architecture:** В Engines добавить узкий формат `mqtt-native-control-v1` и проверку совместимости с одиночной моделью. Web хранит импорт по SHA, фиксирует снимок в задании и проверяет его снова в worker. Итоговое сравнение сохраняется отдельным файлом; исходная сводка с калибровочным reference остаётся неизменной. Существующая очередь и исполнители сохраняются.

**Tech Stack:** C#/.NET 6 Engines, ASP.NET Core 8 Web, xUnit, текущий JavaScript и Playwright.

**Spec:** `MqttY.Web.single-broker-validation.md`, оставшиеся пункты независимого контроля; согласованная серия статьи 1 и авторская граница `docs/dissertation/author-decisions.md`.

## Global Constraints

- Не выполнять новые натурные измерения и не менять frozen profiles/runtime/пороги 15%/20%/0,05/0,05.
- Контроль — три сохранённых запуска после фиксации профиля, отдельная campaign identity и SHA первичных событий; не использовать калибровку под видом контроля.
- Совпадают брокер, профиль, payload, QoS, publishers, один subscriber, политика нагрузки, прогрев, подача и срок наблюдения. При расхождении запуск с этим контролем отклоняется.
- SHA подтверждает целостность, но не истинность пользовательского JSON. В Web проверяются структура и связность происхождения; первичные события предварительно пересчитываются отдельным инструментом. Это ограничение явно показано.
- Без контроля разрешён прежний режим: «сравнение с калибровкой», без отметки новой натурной точности.
- Основной текст диссертации не менять; файлы raw и бинарные сборки хранить вне Git.

## Review Focus

1. Подмена контрольного снимка после постановки задания — worker обязан отклонить SHA mismatch.
2. Калибровочная campaign или совпадающие с профилем исходные публикации — контроль отклоняется.
3. Другой профиль или окна нагрузки — отклонение до запуска, а не сравнение несопоставимых чисел.
4. Нулевой/неразрешённый состав сообщений и неверные знаменатели — некорректный пакет не импортируется.
5. Старый запуск без контроля — калибровочные критерии сохраняются и не переименовываются в независимые.

## Формат

JSON содержит `schemaVersion=1`, `artifactType=mqtt-native-control-v1`, название, broker, profileSha256, calibrationCampaignId, controlCampaignId, profileFrozenUtc, programSha256, auditSha256 и workload. Workload: payloadBytes, qos, publishers, subscribers=1, warmupSeconds, measurementSeconds, drainSeconds, loadPolicy=closedLoopPerPublisher. Три runs имеют уникальный id, stage=control, measurementStartedUtc после freeze, SHA публикаций/доставок/фаз, attempted/completed/failed/completedIdsDelivered/pending, фактический знаменатель подачи и p99PublishMs. Средние рассчитываются сервером по трём запускам; готовое поле «все прошли» не импортируется.
