Актуален на 03.11.2026. Это единственный рабочий план завершения. [Статус](../../reports/status/Progress.md) содержит факты приёмки; [исходные 42 шага](../dissertation/articles-and-work-plan.md) сохраняются только для учёта прежней оценки 47 человеко-дней. Межмашинный бенчмарк и готовность Web учитываются отдельно: они не повышают задним числом процент готовности статей. По решению пользователя сейчас бенчмарк только планируется, запуски отложены.

## Что уже достаточно

Основная серия статьи 1 — 40/40 запусков, 12/12 сравнений в допусках. Дополнительная сессия — 24/24, но только 10/12 сравнений в допусках: два нарушения p99 ActiveMQ остаются ограничением. Для статьи 2 есть 162 сетевых расчёта и 6 повторов; это модели, без доказанной точности реальной федерации. Чувствительность исследована в 216 запусках. Ограниченный benchmark двух исполнителей завершён: 20/20 моделей, ускорение 1,879×. Windows → Linux/e2k проверен в 12 запусках.

**Новых обязательных длинных серий для этих ограниченных утверждений нет.** Ссылки на результаты собраны в [статусе](../../reports/status/Progress.md). Не повторяем всю матрицу для роста числа измерений, не подбираем удачные повторы и не превращаем исследование очереди в бессрочное ожидание полного drain.

Отдельный новый результат — сравнение стоимости исполнения MqttY на разных машинах. Прежний Windows → e2k smoke подтвердил равенство научных результатов; полноценного межмашинного бенчмарка времени, CPU и памяти он не заменяет.

## Межмашинный бенчмарк MqttY

Цель — измерить стоимость одной и той же симуляции на разных вычислительных средах при сохранении научного результата. Измеряется исполнение MqttY, а не пропускная способность настоящего MQTT-брокера. Натурные кампании MqttBenchmark для этого не запускаются.

| Машина | Известное состояние | Что уточнить перед запуском |
| --- | --- | --- |
| Текущая Windows-машина | Доступна локально; использовалась для baseline | Модель CPU, архитектура, RAM, runtime, свободные ресурсы |
| `10.100.101.14` | Ранее проверенный Linux/Эльбрус; научный smoke прошёл | Текущий runtime и ресурсы, способ сохранить задание после выхода из SSH |
| `10.10.144.66` | Дополнительная машина, указанная пользователем; ОС и архитектура не проверены | ОС, архитектура, CPU/RAM, runtime и доступность стенда |

Целевой охват — Windows x64, Linux x64 и Linux/e2k. Роль `10.10.144.66` определится после проверки среды; до этого она не считается подтверждённым Linux x64 стендом. Пароли и другие секреты в пакет и отчёт не включаются. Проверка среды и запуски сейчас не выполняются.

| Этап | Ограниченная программа | Критерий готовности |
| --- | --- | --- |
| B1. Зафиксировать пакет | Один commit корневой `develop` и его gitlink-версии; Release-сборка без RID/apphost, одинаковые DLL и входы, manifest SHA. Паспорта CPU/ОС/runtime/GC/ресурсов всех стендов | Пакет проверяется по хэшам на каждой машине; различия среды перечислены |
| B2. Выбрать три фиксированные задачи | Один брокер с небольшой нагрузкой; более нагруженный одиночный брокер; небольшая сеть брокеров. Общие seed, профиль, топология, число сообщений, модельное время, tick, drain и режим журналирования. Одна пилотная попытка на задачу и машину; после пилота единая матрица замораживается | Длительности позволяют измерять вычисление; определены общие лимиты времени, RAM и диска. Несовместимость сетевого движка явно фиксируется, задача молча не подменяется |
| B3. Выполнить повторы | По пять учётных запусков каждой задачи в новом процессе, один исполнитель, одинаковый порядок: всего 15 учётных запусков на машину. Пилоты в статистику не входят; новых комбинаций QoS/payload/seed не добавляем | Все попытки, включая ошибки и таймауты, сохранены; нет повторов до получения удобного результата |
| B4. Проверить результат и стоимость | Научные fingerprints сравниваются с общим эталоном и между повторами. Измеряются wall time процесса, user+system CPU, peak working set/RSS, объём результата и выполненная работа | Несовпадение научных данных блокирует вывод об ускорении; незавершённые прогоны не сравниваются как одинаковая работа |
| B5. Выпустить один итоговый отчёт | На каждую задачу: все пять значений, медиана, min/max, отношение медиан к выбранному baseline, CPU и память; паспорта сред, версии, команды, хэши и ограничения | Есть воспроизводимый пакет и таблица сравнения по подтверждённым стендам; непроверенные платформы явно остаются открытыми |

Основная величина — время от старта процесса до его завершения, включая запуск .NET/JIT и запись одинакового набора артефактов. Сборка, передача по SSH и последующая проверка файлов в это время не входят. Пилот отдельного процесса не считается прогревом JIT учётного процесса; политика файлового кэша и фоновой нагрузки записывается. Показатели CPU и памяти получают средствами ОС с указанием метода: working set и RSS не объявляются тождественными. Если счётчик недоступен, это пропуск, а не нулевое значение.

Сравнение разных машин показывает эффект всей среды: CPU, ОС, runtime и хранилища. При различающихся версиях .NET нельзя приписывать отношение времени только процессору или ОС. Для вывода именно о Windows против Linux нужен отдельный контроль на одном оборудовании; в минимальную программу он не входит. Многоисполнительный режим и полная матрица аппаратных настроек также отложены: имеющийся результат workers1/2 остаётся самостоятельным измерением.

Бюджет основной серии рассчитывается после пилота по самой медленной машине и фиксируется до старта. Общие задачи нельзя облегчать только для Эльбруса. Если единая задача не укладывается в лимит, сохраняется таймаут; изменение программы требует новой общей версии протокола. Фоновый запуск допускается только после проверки, что он переживает закрытие SSH. После подтверждения старта агент останавливается; длительный мониторинг и сбор результатов выполняются по следующему поручению пользователя.

## Приёмка веб-версии MqttY

Исторические проверки подтверждают работающий прототип и отдельные сценарии: [сводка Web](../../reports/web/README.md). **Текущий релиз ещё не объявлен готовым:** старые квитанции относятся к своим версиям. Цель — воспроизводимый внутренний Linux x64 релиз с ограниченным набором функций; команда развёртывания и ограничения приведены в [руководстве](../mqtty/web-deployment.md).

| Критерий | Что проверить на зафиксированном кандидате | Что сохранить |
| --- | --- | --- |
| W1. Сборка и установка | Чистая сборка выбранного commit `develop`, manifest файлов и профилей; установка на поддерживаемый Linux, успешный health; явно указаны runtime и архитектура | SHA исходников, manifest, команды, версии среды |
| W2. Пользовательский путь | Создать/изменить/сохранить/загрузить топологию; короткий запуск каждого из трёх поддерживаемых движков; просмотр прогресса, пауза/продолжение/отмена; некорректный ввод и отсутствующий профиль дают понятную ошибку, без молчаливой подмены идеальной моделью | Идентификаторы заданий, квитанция проверки UI, изображения результата ручной приёмки |
| W3. Результаты | Экспорт доступен, summary соответствует файлу задания, seals проверяются; повтор малого детерминированного сценария даёт те же научные показатели. Runtime CPU/RSS отделены от модельных ресурсов | Хэши экспорта, сравнение одного повтора, список проверенных показателей |
| W4. Эксплуатация | Служба переживает выход из SSH; перезапуск не теряет завершённые результаты и не запускает их молча повторно; ограничения времени/памяти/диска и ошибки хранилища проверены; журналы доступны | Проверка systemd/linger, сохранности данных и ограничений; инструкция восстановления |
| W5. Приёмка | Пользователь проходит основной сценарий, известные ограничения записаны, нет блокирующего дефекта W1–W4 | Решение о готовности с датой и SHA релиза |

Проверки W2–W4 ограничены короткими функциональными сценариями и одним повтором; полные кампании 40/162/216 заново не запускаются. Минимальную матрицу и лимит времени фиксируем до запуска, дефекты устраняем по месту. Доступ первой версии — через SSH к `127.0.0.1`, без публичного размещения интерфейса без аутентификации. Готовность Web на Linux x64 не означает готовность Web на e2k: проведённый e2k smoke относится к переносимой симуляции.

За пределами первой приёмки: произвольный граф балансировки, разные профили у каждого брокера, undo/redo, durable checkpoint вычисления, импорт внешней CLI-очереди, публичные аккаунты и полное управление натурными кампаниями из браузера. Эти функции не блокируют завершение согласованного внутреннего релиза.

## Когда всё-таки нужен новый замер

Помимо отдельно запланированного межмашинного бенчмарка B1–B5, новые научные измерения нужны только если конкретное замечание проверяющего выявило недостаток доказательств или автор расширил утверждение. До запуска записываются вопрос, изменяемый фактор, минимальное число точек, предел времени/ресурсов и критерий остановки. Сначала пересчитываются уже сохранённые данные; если их достаточно, новый запуск отменяется.

Для очереди 4096 сохранён результат к 40 модельным секундам: 76 513 из 200 000 пар доставки. Это не полный drain; сравнение с 38 609 для очереди 1024 допустимо в том же окне. Длинный хвост нужен только при новом утверждении о полном завершении. Историческое ускорение 12,5× не восстанавливаем серией подбора: используем измеренные 1,879× для набора независимых моделей с указанной стоимостью памяти.
