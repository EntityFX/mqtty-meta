# Переход исследовательских запусков на MqttY Web

> Для исполнителя: выполнять по шагам с writing-plans, test-driven-development и verification-before-completion. Причины отказов устанавливать через systematic-debugging. Текущий статус сначала отражать в `reports/status/Progress.md`.

**Цель:** опубликовать накопленный веб-код, обновить Linux Web и подтвердить выполнение ограниченной серии через его очередь, сохранив научную программу и прежние данные.

**Архитектура:** браузер и Web API управляют заданиями, существующие runners MqttY исполняют модели в отдельных процессах. MqttBenchmark остаётся измерителем настоящего брокера. Неподдерживаемый тип опыта не заменяется другим движком.

**Средства:** ASP.NET Core 8, существующий проект `EntityFX.Tests.Web`, JavaScript, Python-проверки, systemd и Linux-хранилище доказательств.

**Основание:** `MqttY.Web.SDD.md`, выбранная минимальная программа статьи 1 и поручение автора переходить на Web по возможности.

## Ограничения

- Исторические runtime, профили, результаты и deadline сохраняются. Публикация кода не означает публикацию научных данных внешним пользователям.
- Не включать в Git базы Web-заданий, временные файлы IDE, логи и полные архивы.
- Linux Web доступен через loopback и SSH-туннель; один worker, ограниченные память и очередь.
- Не переключать release при живых заданиях. До переключения подготовить проверенную сборку и возможность возврата на прежний release.
- Проверка Web не подтверждает точность реального брокера. Первая статья требует собственной калибровки и отдельного контроля; вторая — объявленного фактического покрытия сети.

## Особое внимание

1. Сохранённые топологии и пресеты остаются доступны после обновления; результаты не удаляются.
2. Поиск/страницы заданий содержат имя, статус и время; параметры тика не теряются.
3. Изменение профиля создаёт новую проверенную копию и не меняет входы уже поставленного задания.
4. Пользовательский тип брокера принимается только с подходящим профилем; отсутствие точки не подменяется соседней.
5. Успех API, завершение worker и целостность научного результата проверяются отдельно.
