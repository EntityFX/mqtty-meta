# Краткое руководство по проекту

Проект связывает измерение настоящих MQTT-брокеров и моделирование. MqttBenchmark получает наблюдения; MqttY строит профиль и воспроизводит выбранные характеристики. Результат сравнивают с натурными данными, отдельно проверяя скорость, задержки, ошибки и доставку.

## Роли приложений

| Часть | Назначение |
| --- | --- |
| MqttBenchmark | Настоящие MQTT-соединения, нагрузка, журнал публикаций и получений, сведения о стенде |
| MqttY | Модель клиентов, брокеров и сети; профиль из измерений, повторяемые симуляции |
| Web MqttY | Редактор топологии, настройка и запуск поддерживаемых модельных заданий, просмотр состояния и результатов |
| Скрипты мета-репозитория | Программы опытов, независимый пересчёт сохранённых событий, таблицы, проверки и отчёты |
| `diss/` | Основной текст диссертации; его редактирует автор |

## Путь от измерения к выводу

1. Зафиксировать брокер, стенд, код, нагрузку, временные окна и правила сравнения.
2. Проверить запуск коротким пилотом. Пилот подтверждает работоспособность, а не точность модели.
3. Измерить реальный брокер, сохраняя попытки, исходы публикаций и сообщения получателя.
4. По калибровочной серии построить профиль. Отсутствующий режим не подменять соседним.
5. Выполнить модельные запуски и отдельные натурные контроли, не перестраивая профиль по результату проверки.
6. Сравнить значения, проверить повторы и описать расхождения. Полное покрытие программы не означает прохождения научных критериев.

Время вычисления на компьютере отличается от модельного времени. Подтверждение публикации отправителю отличается от доставки подписчику. Ошибка клиентского вызова не обязательно означает отказ брокера. Точные определения находятся в [контракте измерений](measurement-contract.md).

## Где хранятся результаты

Код находится в подмодулях `MqttBenchmark/` и `mqtty/`. Руководства — в `docs/`, принятые отчёты — в `reports/analysis/`, данные и квитанции проверок — в `reports/data/` и `reports/audits/`. Полные первичные архивы хранятся вне Git; пути и контрольные суммы входят в реестры результатов.

Историческая программа 1512 запусков сохранена отдельно от новых серий статей. Её нельзя смешивать с новой серией 40/40 или сетью 162+6. Дата отчёта и идентичность входов определяют, к какому эксперименту относится число.

Это краткий вход в документацию. Подробные определения, команды и результаты имеют по одному основному источнику по ссылкам выше.
