# Каталог топологий MqttY

Здесь собраны типовые схемы и топологии наших сетевых опытов. **Синие узлы в учебных SVG — брокеры, серые — сетевые узлы без брокера.** Связи шаблонов двусторонние. Это каталог документов: JSON-описания не объявляются готовыми пресетами импорта Web.

## Типовые топологии

| Схема | Брокеров | Сетевых узлов без брокера | Связей | Для чего полезна |
| --- | ---: | ---: | ---: | --- |
| [Линия](templates/line/README.md) | 5 | 0 | 4 | Много последовательных переходов; удалённые края сети |
| [Кольцо](templates/ring/README.md) | 6 | 0 | 6 | Цикл, повторные прибытия, альтернативные направления |
| [Звезда с транзитом](templates/star-transit/README.md) | 4 | 1 | 4 | Общая физическая точка прохождения трафика, без брокера в центре |
| [Полный граф](templates/mesh/README.md) | 5 | 0 | 10 | Все пары соседей; много связей и повторных прибытий при flooding |
| [Ромб](templates/diamond/README.md) | 4 | 0 | 4 | Два пути от одного края к другому |
| [Дерево](templates/tree/README.md) | 7 | 0 | 6 | Иерархия без циклов |
| [Три площадки через транзит](templates/hierarchical/README.md) | 9 | 1 | 12 | Локальные группы брокеров и общий внешний сетевой узел |

Каждый каталог содержит `topology.json` с узлами/связями, `topology.mmd` и `topology.svg`. Шаблоны не обозначают выполненный опыт, не задают MQTT-маршруты, нагрузку или параметры каналов. Чтобы запускать их в симуляторе, отдельно нужны поддерживаемая конфигурация и проверка графа.

## Фактические схемы исследований

| Опыт | Что сохранено | Статус и границы |
| --- | --- | --- |
| [Четыре площадки: линия](studies/main-line4/README.md) | Физическая линия и логические маршруты Relay «каждый каждому» | Схемы конкретного проверенного результата основной серии |
| [Четыре площадки: кольцо](studies/main-ring4/README.md) | Физическое кольцо и логические маршруты Relay «каждый каждому» | Схемы конкретного проверенного результата основной серии |
| [Десять брокеров через транзит](studies/relay-transit10/README.md) | 11 физических узлов и 90 логических направлений Relay | Отдельная завершённая короткая программа; не десять брокеров плюс одиннадцатый центральный брокер |
| [Балансировщик: три backend-брокера](studies/load-pool3/README.md) | Клиенты, назначение перед CONNECT, промежуточные сетевые сегменты | Исходная схема load-balancing-study-v1; это не схема межброкерной федерации |
| [Один Mosquitto, 64 отправителя](studies/single64/README.md) | Центральный брокер, клиентский сегмент и сетевые переходы | Исходная схема сравнения балансировки; не профиль для любого числа отправителей |

У исследований с двумя схемами **физический граф** показывает сетевые пути, а **логический** — MQTT-маршруты брокеров. Прямая логическая связь может проходить через несколько физических сегментов. В исходных схемах используется собственное оформление, сохранённое без изменения.

Основная Linux-программа линии/кольца/звезды ещё выполняется: наличие этих схем не означает приёмки всей матрицы. Звезда текущей программы показана пока только как [типовой образец](templates/star-transit/README.md); её фактические схемы будут добавлены из принятого результата. Число запусков и текущий статус смотрите в [Progress.md](../../reports/status/Progress.md).

## Источники и дальнейшее использование

[catalog.json](catalog.json) содержит тип записи, число брокеров/узлов, пути, исходники и SHA-256 скопированных схем. Копии опытов побайтно совпадают с источниками. Полные журналы, runtime и архивы не дублируются здесь.

Для статьи и диссертации выбирайте `studies`, когда описываете выполненный опыт, и `templates`, когда объясняете структуру. Для механизма федерации см. [контракт](../dissertation/network-model-contract.md) и [условия пересылки](../dissertation/network-forwarding-proofs.md). Для работы в Web см. [план одиночной проверки](../plans/MqttY.Web.single-broker-validation.md).
