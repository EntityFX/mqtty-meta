# Ускоренное продолжение Linux-кампании

`accelerated-resume.py` — адаптер к замороженному MqttBenchmark `3a68946`.
Он запускается через существующий owned systemd launcher, с прежними CPU affinity,
8 GiB MemoryMax и внешним диском hd250. Измерительный benchmark и simulator
`0fc65a2` не изменяются; калибратор остаётся `55a87f1`.

Пользователь 15 октября 2026 разрешил сократить только новые симуляции:
warmup 5 с, measurement **10 с**, drain максимум 30 с, tick 0,1 мс.
Натурные измерения сохраняют measurement 30 с и прежний захват телеметрии.
Матрица, три seeds, профили, offered load, модель транспорта и пороги сохраняются.
Сокращение окна уменьшает число наблюдений и статистическую устойчивость p99.

Полная прежняя выборка Aedes `fidelity` из 72 симуляций с measurement 30 с
остаётся на месте. Новые выборки размещаются в каталогах `*-10s`; каждый index
содержит длительность, каждый experiment manifest — точные ticks, каждый отчёт —
длительность каждой строки. Выборки с разной длительностью не объединяются в
один статистический результат. Native calibration и holdout остаются раздельными.

До четырёх независимых процессов BrokerFidelity и до двух MqttRelay выполняются
одновременно; внутри каждого `parallel=false`, `refreshStrategy=0`.
Симуляции не пересекаются с натурными измерениями. Индекс записывает только
проверенные завершённые процессы; fidelity exit 3 сохраняется как научный результат,
другой ненулевой exit останавливает этап, отменяя оставшихся owned children.
Профиль проверяется после каждого завершения. Результаты сортируются по ключу,
независимо от порядка завершения процессов. Проверки диска и ограничения памяти
предотвращают переполнение; ошибки не разрешают очистку evidence.

В отдельном Linux pilot четыре неизменённых 30-секундных сценария завершились за
45,60 с против суммарных 167,30 с в основной последовательной серии: ускорение
3,67 раза. Scientific summaries, latency histograms, broker и receiver counters
совпали. Pilot исключён из основного покрытия. Это измерение не гарантирует
такого же ускорения для всех нагрузок или MqttRelay.

Дополнительно адаптер исправляет только чтение старого GraphML для отчётов:
экспортёр записал UTF-8 bytes с объявлением UTF-16. Декларация исправляется
в памяти; исходный GraphML не переписывается. Настоящий UTF-16 читается штатно,
некорректный XML остаётся ошибкой. Натурные результаты и модель не меняются.

Проверки адаптера:

Позднее пользователь разрешил повысить MqttRelay с двух до четырёх процессов:
измеренный RSS тяжёлого процесса около 0,75 GiB; запас CPU и памяти достаточен.
`relay-concurrency-handoff.py` записывает новый лимит и ждёт завершения текущего
этапа Aedes/relay. На границе он останавливает только owned controller, повторно
проверяет отсутствие active workloads и дочерних процессов и возобновляет ту же
серию новым контроллером. Текущие прогоны не прерываются. Все источники,
хэши, состояния до/после и service identities сохраняются в revision-transition.
